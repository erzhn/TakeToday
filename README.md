# TakeToday

TakeToday — учебный веб-сервис для покупки непроданной еды со скидкой. Сейчас реализованы регистрация, подтверждение почты, вход с кодом из письма, выход, восстановление пароля и главные страницы для разных ролей. Предложения еды, покупки, платежи и редактирование профиля пока не реализованы.

Бэкенд и фронтенд запускаются отдельно и общаются через API.

## Что установить

- JDK 17 или новее — для бэкенда. Нужен именно JDK с компилятором javac.
- Node.js 20 или новее — для фронтенда.
- Docker с Docker Compose — для PostgreSQL и тестовой почты Mailpit. На Windows подойдёт Docker Desktop.
- Браузер; Postman — по желанию.

Отдельный Maven не нужен: проект содержит Maven Wrapper. Для первого запуска нужен интернет, чтобы скачать Maven, зависимости и Docker-образы.

Проверьте программы в терминале:

```text
java -version
javac -version
node --version
docker --version
docker compose version
```

Если команда не найдена, установите программу, добавьте её в PATH и откройте новый терминал. JAVA_HOME, если задан, должен указывать на папку JDK.

## Запуск на Windows

### 1. Откройте папку проекта

Скачайте или клонируйте репозиторий. Откройте PowerShell в корне проекта — там, где находятся pom.xml и compose.yaml. Все следующие команды выполняются из этой папки.

### 2. Создайте настройки

```powershell
Copy-Item .env.example .env
notepad .env
```

Если .env уже существует, используйте его, не перезаписывая свои настройки. Замените DB_PASSWORD на свой пароль, например YourLocalDbPassword123. Остальные значения для запуска с Docker оставьте из примера.

```dotenv
DB_URL=jdbc:postgresql://localhost:5433/taketoday
DB_USER=taketoday
DB_PASSWORD=YourLocalDbPassword123
PORT=8080
FRONTEND_ORIGIN=http://localhost:5173
SMTP_HOST=localhost
SMTP_PORT=1025
SMTP_AUTH=false
SMTP_STARTTLS=false
SMTP_USER=
SMTP_PASSWORD=
MAIL_FROM=no-reply@taketoday.local
COOKIE_SECURE=false
ADMIN_EMAIL=
ADMIN_PASSWORD=
```

Пишите одну переменную на строку, без пробелов вокруг = и без кавычек вокруг значения: Windows-скрипт читает их буквально. Не добавляйте комментарии в конце строки с паролем. Файл .env исключён из Git; не публикуйте его.

### 3. Запустите PostgreSQL и почту

Сначала запустите Docker Desktop, затем:

```powershell
docker compose up -d
docker compose ps
```

Первый запуск может занять несколько минут. Дождитесь статуса healthy у PostgreSQL; Mailpit должен быть запущен. База taketoday и пользователь создаются автоматически.

### 4. Запустите бэкенд

В первом окне PowerShell:

```powershell
.\start-backend.ps1
```

Дождитесь сообщения о запуске TakeTodayApplication. Таблицы создадутся автоматически через Flyway. Оставьте окно открытым.

Если Windows запрещает выполнение скрипта, используйте настройку только для нового процесса:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-backend.ps1
```

### 5. Запустите фронтенд

Во втором окне PowerShell из корня проекта:

```powershell
.\start-frontend.ps1
```

При запрете выполнения скриптов:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-frontend.ps1
```

Сборка и npm install для текущего фронтенда не нужны: он использует обычный JavaScript и встроенные модули Node.js.

### 6. Откройте сайт

| Адрес | Назначение |
| --- | --- |
| http://localhost:5173 | Сайт TakeToday |
| http://localhost:8025 | Mailpit: письма с кодами |
| http://localhost:8080/api/auth/me | Текущий пользователь API; без входа роль GUEST |
| http://localhost:8080/api/public/home | Публичная главная API |

Бэкенд на 8080 предоставляет API: открывать сайт нужно на 5173. Используйте localhost последовательно, не смешивайте его с 127.0.0.1. Вход в браузере и вход в Postman — отдельные сессии.

## Проверка через браузер

1. Откройте сайт: главная доступна гостю без регистрации.
2. Нажмите «Регистрация», выберите покупателя, укажите имя, новую почту и пароль. Пароль — от 10 символов, не более 72 байт UTF-8.
3. Откройте Mailpit, найдите письмо для указанной почты и скопируйте шестизначный код.
4. Введите код на сайте: откроется главная покупателя.
5. Выйдите и войдите снова. При каждом входе после пароля требуется новый код из письма.
6. Проверьте «Забыли пароль?»: получите код, задайте новый пароль и войдите с ним.
7. Зарегистрируйте сотрудника с другой почтой. Выберите «Представлять заведение», заполните его сведения и подтвердите код. На главной появятся данные этого заведения.

Одну почту нельзя зарегистрировать дважды. Код действует 10 минут, используется один раз и допускает не более пяти неверных попыток. Между письмами одному аккаунту нужно ждать 60 секунд; частые попытки ограничиваются на 15 минут.

Mailpit перехватывает письма локально, не отправляя их в интернет. Для тестирования подойдёт customer-test@example.com: письмо появится в Mailpit. Это не доказывает существование реального ящика. Для такой проверки настройте реальный SMTP и получите код в почтовом ящике.

## Роли и администратор

| Роль | Что доступно сейчас |
| --- | --- |
| Гость | Публичная главная, регистрация и вход; защищённые действия недоступны |
| Покупатель | Главная покупателя после подтверждения входа |
| Сотрудник заведения | Главная сотрудника и сведения своего заведения |
| Администратор | Главная администратора |

Администратор создаётся при старте бэкенда. Добавьте в .env и перезапустите бэкенд:

```dotenv
ADMIN_EMAIL=admin@example.com
ADMIN_PASSWORD=YourAdminPassword123
```

Войдите через обычную форму и код из письма. Публичная регистрация ADMIN запрещена. ADMIN_EMAIL не должен быть занят другой ролью. Изменение ADMIN_PASSWORD не меняет пароль уже созданного администратора; для него используйте восстановление доступа.

## Проверка через Postman

Импортируйте [коллекцию из 22 запросов](postman/TakeToday.postman_collection.json). Подробные сценарии и скрипты находятся в [инструкции Postman](postman/README.md).

- baseUrl: http://localhost:8080; No Auth, cookie jar включён.
- Перед каждым POST выполняйте запрос 01 для CSRF-токена.
- Код из письма записывайте в переменную code, сохраняя начальные нули.
- После подтверждения входа и выхода снова получите CSRF-токен.
- Не запускайте всю коллекцию подряд: сценарии требуют разных ролей и ожидания писем.

## Запуск на Linux и macOS

Установите те же JDK, Node.js и Docker Compose. В корне проекта:

```bash
cp .env.example .env
```

Отредактируйте .env и задайте DB_PASSWORD. Для следующего способа загрузки используйте значения, допустимые в shell, например пароли из букв и цифр без пробелов; окончания строк файла — LF. Загружайте только собственный проверенный .env: shell исполняет его содержимое.

```bash
docker compose up -d
set -a
. ./.env
set +a
sh ./mvnw spring-boot:run
```

Во втором терминале из корня проекта:

```bash
cd frontend
npm start
```

Откройте http://localhost:5173 и http://localhost:8025.

## Если PostgreSQL уже установлен

Docker необязателен: можно использовать собственный PostgreSQL и SMTP. В pgAdmin или psql под администратором выполните команды по отдельности. CREATE DATABASE выполняется вне транзакции:

```sql
CREATE USER taketoday WITH PASSWORD 'YourLocalDbPassword123';
CREATE DATABASE taketoday OWNER taketoday;
```

Укажите в .env адрес своего сервера, например:

```dotenv
DB_URL=jdbc:postgresql://localhost:5432/taketoday
DB_USER=taketoday
DB_PASSWORD=YourLocalDbPassword123
```

Таблицы создаст бэкенд при старте. Для регистрации и входа нужен также SMTP: Mailpit или реальная почта.

## Реальная отправка email

Узнайте SMTP-параметры у почтового провайдера. Пример для SMTP с STARTTLS:

```dotenv
SMTP_HOST=smtp.your-provider.example
SMTP_PORT=587
SMTP_AUTH=true
SMTP_STARTTLS=true
SMTP_USER=your-mailbox@example.com
SMTP_PASSWORD=YourMailAppPassword
MAIL_FROM=your-mailbox@example.com
```

Замените все значения на данные провайдера. Возможно, понадобится пароль приложения. Адрес MAIL_FROM должен быть разрешён SMTP-сервером. Перезапустите бэкенд; коды ищите в реальном ящике, включая папку «Спам».

## Остановка и повторный запуск

Остановите бэкенд и фронтенд через Ctrl+C в их терминалах. Затем:

```text
docker compose down
```

Данные PostgreSQL сохраняются в Docker volume. При следующем запуске повторите docker compose up -d и запустите оба приложения. Не используйте down -v для обычной остановки: он удаляет volume с базой. Изменение DB_PASSWORD в .env не меняет пароль пользователя в уже созданной базе: используйте исходный или измените его средствами PostgreSQL.

## Проверки кода

Windows, из корня проекта:

```powershell
.\mvnw.cmd test
npm --prefix frontend run check
```

Linux/macOS:

```bash
sh ./mvnw test
npm --prefix frontend run check
```

Java-тесты используют H2 в режиме совместимости PostgreSQL и подменённую почту. PostgreSQL и SMTP для них не нужны. Они не заменяют проверку с настоящей базой. Команда check проверяет синтаксис JavaScript.

## Решение частых проблем

| Проблема | Что сделать |
| --- | --- |
| Команда java/javac/node не найдена | Проверить установку, PATH, JAVA_HOME; открыть новый терминал |
| Maven не скачивает зависимости | Проверить интернет и доступ к Maven Central |
| Docker недоступен | Запустить Docker Desktop или службу Docker |
| PostgreSQL connection refused | Проверить DB_URL, порт и docker compose ps; дождаться healthy |
| PostgreSQL password authentication failed | Проверить пароль, установленный при первом создании базы |
| Порт занят | Освободить 5173/8080/5433/1025/8025 либо согласованно изменить настройки |
| HTTP 503 при отправке кода | Проверить SMTP/Mailpit и настройки .env |
| HTTP 403 в Postman | Обновить CSRF через запрос 01 и проверить cookie jar |
| HTTP 409 при регистрации | Почта уже занята: использовать другую или восстановить доступ |
| HTTP 429 | Подождать 60 секунд между письмами либо завершения 15-минутного ограничения |
| Вместо сайта ошибка на 8080 | Открыть фронтенд на 5173 |

Логи базы и почты:

```text
docker compose logs postgres
docker compose logs mailpit
```

После изменения .env перезапускайте бэкенд. Если изменили его PORT, укажите новый адрес API в терминале фронтенда перед запуском:

```powershell
$env:API_URL = 'http://localhost:8081'
.\start-frontend.ps1
```

Фронтенд сам не загружает .env. Его порт задаётся переменной FRONTEND_PORT в терминале фронтенда. Если меняете этот порт, измените FRONTEND_ORIGIN в .env бэкенда. Если меняете порт бэкенда, также обновите baseUrl в Postman.

## Структура проекта

```text
src/main/java/       Бэкенд и REST API
src/main/resources/  Настройки и миграции базы
src/test/java/       Тесты авторизации
frontend/            Сайт и Node.js-сервер с прокси API
postman/             Коллекция и инструкция Postman
compose.yaml         PostgreSQL и Mailpit
.env.example         Пример настроек
start-backend.ps1    Запуск бэкенда на Windows со чтением .env
start-frontend.ps1   Запуск фронтенда на Windows
```

Инструкция описывает локальную разработку. Для публичного размещения потребуются HTTPS, безопасные cookies, реальный SMTP и резервное копирование базы.
