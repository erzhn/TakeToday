# TakeToday

Веб-сервис, на котором кафе, пекарни и другие заведения продают оставшуюся к концу дня еду со скидкой.
Покупатель выбирает набор, полностью оплачивает его на сайте и забирает в заведении по шестизначному коду или QR-коду.

Учебный проект по дисциплине «Технология командной разработки ПО», КГТУ им. И. Раззакова, группа ПИ(б)-2-24.

**Команда:** Таалайбеков Жаныбек, Союзбеков Эржан
**Преподаватель:** ст. преп. Сабаева К. К.

## Технологии

- Java 17, Spring Boot 3.4
- Spring MVC + Thymeleaf (страницы рендерит сервер)
- Spring Security (вход, роли)
- Spring Data JPA + PostgreSQL 16
- Flyway (миграции базы данных)
- JUnit 5, H2 (тесты)

## Запуск

### Что нужно установить
- JDK 17 или новее
- IntelliJ IDEA (Maven встроен)
- PostgreSQL 16: через Docker Desktop **или** обычной установкой

### 1. База данных

**Через Docker:**
```
docker compose up -d
```

**Без Docker:** создайте в PostgreSQL пользователя `taketoday` с паролем `taketoday` и базу `taketoday`:
```sql
CREATE USER taketoday WITH PASSWORD 'taketoday';
CREATE DATABASE taketoday OWNER taketoday;
```

Таблицы создаются автоматически при запуске приложения (Flyway).

### 2. Приложение
Откройте проект в IntelliJ IDEA и запустите `TakeTodayApplication`.
Сайт откроется на http://localhost:8080

Другие параметры подключения задаются переменными окружения `DB_URL`, `DB_USER`, `DB_PASSWORD` (см. `.env.example`).

### Тестовые пользователи (профиль `dev`)
| Почта | Роль | Пароль |
|---|---|---|

### Тесты
IntelliJ: Maven → Lifecycle → `verify`. Для тестов PostgreSQL не нужен — используется H2 в памяти.

## Правила работы с репозиторием

- `main` — стабильная версия, сдаётся на этапах. Напрямую не пушим.
- `develop` — общая ветка разработки.
- `feature/<задача>` — ветка под каждую задачу, создаётся от `develop`.
- Каждая задача попадает в `develop` через Pull Request с проверкой второго участника.
- В конце этапа `develop` сливается в `main`, ставится тег `v0.2`, `v0.4`, … `v1.0`.

**Сообщения коммитов:** `тип: что сделано (#номер задачи)`
- `feat:` — новая функция
- `fix:` — исправление
- `refactor:` — переделка без изменения поведения
- `docs:` — документация
- `test:` — тесты
- `chore:` — настройки, зависимости

**Миграции базы:** существующие файлы `V*.sql` не меняем, только добавляем новые со следующим номером.
