# TakeToday

Сервис для покупки оставшейся к концу дня еды со скидкой. Backend: Java 17+, Spring Boot 3.5.6, Spring Security, PostgreSQL и Flyway. Интерфейс: HTML, CSS и JavaScript без отдельной сборки.

## Предложения в кабинете заведения (этап 2, Эржан)

Сотрудник заведения (`STAFF`) управляет только своими наборами; чужой набор по прямой ссылке отвечает 404.

| Адрес | Что |
| --- | --- |
| `/staff` | Таблица «Управление предложениями»: фото, цена и скидка, остаток порций, окно выдачи; фильтры «Все / Активно / Снято / Время вышло» и поиск |
| `/staff/offers/new` | Новое предложение: название, вид еды, состав, фото (JPG/PNG до 5 МБ), цены, порции, дата и время выдачи; справа — карточка «Так увидит покупатель» |
| `/staff/offers/new?from={id}` | «Повторить» прошедший набор: те же данные и фото, выдача сегодня |
| `/staff/offers/{id}/edit` | Изменение. Порций нельзя сделать меньше, чем забронировано и оплачено |
| `POST /staff/offers/{id}/withdraw`, `/resume` | Снять с продажи / вернуть в продажу |

Фото сохраняются в `UPLOAD_DIR/offers` и отдаются по `/uploads/offers/...`. Сервер проверяет не только тип файла, но и его первые байты. Проверки: `.\mvnw.cmd -Dtest=StaffOfferPageTests test`.

## Оплата и код получения (этап 3, Эржан)

Покупатель бронирует набор (страница Жаныбека `/reservations/{id}`, таймер 3 минуты) и жмёт **«Перейти к оплате»**. Открывается учебная платёжная служба — настоящие деньги не списываются.

| Карта | Результат |
| --- | --- |
| `4242 4242 4242 4242` | Оплата прошла → `/orders/{id}`: код `482 913`, QR-код, адрес и время выдачи |
| `4000 0000 0000 0002` | «Недостаточно средств» → бронь сохраняется, кнопка «Попробовать оплатить ещё раз» |
| Любой другой номер по алгоритму Луна | Оплата прошла |

Срок — любой будущий (`12/28`), CVV — любые 3 цифры. Сохраняются только последние 4 цифры карты.

- **Поздняя оплата:** откройте страницу оплаты и подождите больше 3 минут, потом оплатите — заказ отменится, порции вернутся в продажу, деньги помечены к возврату.
- **Служба недоступна:** в `.env` поставьте `PAYMENT_MOCK_AVAILABLE=false` и перезапустите — «Платёжная служба временно недоступна…», бронь не снимается.
- Все события оплаты пишутся в таблицу `audit_log`: `SELECT event_type, details, created_at FROM audit_log ORDER BY created_at DESC;`
- Проверки: `.\mvnw.cmd "-Dtest=Payment*Tests,MockCardTests,SellerOfferToBuyerTests" test`. `SellerOfferToBuyerTests` проходит путь целиком: продавец выкладывает набор с фото → покупатель видит его в каталоге → бронирует → оплачивает → получает код.

## Выдача заказа (этап 4, Эржан)

Сотрудник открывает **«Выдача заказа»** (`/staff/pickup`) и сканирует QR-код с экрана покупателя («Включить камеру») или вводит 6 цифр. Сервер показывает заказ: что выдать, сколько порций, имя покупателя (сокращённо) и окно выдачи. Кнопка **«Подтвердить выдачу»** переводит заказ в «Выдан», код после этого не действует. У покупателя страница заказа сама меняется на «Заказ выдан».

| Ситуация | Что видит сотрудник |
| --- | --- |
| Не 6 цифр | «Введите 6 цифр кода» |
| Такого кода нет | «Код не найден. Проверьте цифры» |
| Заказ другого заведения | «Этот заказ из другого заведения» (сам заказ не показываем) |
| Уже выдан / повторное нажатие | «Заказ уже выдан {дата, время}» |
| Отменён | «Заказ отменен» |
| Окно выдачи прошло | «Время получения истекло» |
| Окно ещё не началось | Предупреждение, выдать можно |
| 10 неверных кодов за 10 минут | Пауза 10 минут — защита от подбора |

- **Камера** работает только на `https://` или `localhost`. С телефона по адресу вида `http://192.168.…` браузер камеру не даст — тогда кнопка «Распознать QR с фото» (снимок камерой телефона) или ручной ввод. QR распознаётся встроенным `BarcodeDetector` браузера, а где его нет — библиотекой jsQR (`static/js/vendor`, Apache 2.0).
- **Кабинет `/staff`**: «Оплачено сегодня», выручка, «Выдано сегодня», «Ожидают выдачи» — настоящие цифры.
- Миграция `V9__pickup_issue` (на Java, `src/main/java/db/migration`): статусы `ISSUED` и `PICKUP_EXPIRED`, поля `issued_at`, `issued_by`.
- Проверки: `.\mvnw.cmd "-Dtest=Pickup*Tests" test`.

## Каталог и база предложений

Реализована покупательская часть п. 4.3 ТЗ: список наборов, подробности, поиск по названию и совместные фильтры по виду еды, цене со скидкой и времени получения. Каталог и фотографии доступны без входа. Создание и редактирование предложений продавцом, бронирование и оплата пока не реализованы.

- Каталог: http://localhost:8080/catalog (ссылка также есть на главной и в шапке кабинетов).
- Набор: `/offers/{uuid}`.
- Пример фильтра: `/catalog?q=выпечка&type=BAKERY&minPrice=100&maxPrice=500&pickupAfter=18:00&pickupBefore=21:00`.
- `page` — номер страницы с нуля, по 12 наборов; фильтры сохраняются при переключении страниц.
- Поиск без учёта регистра, по части названия набора; `%`, `_` и `!` трактуются как обычные символы. Все значения передаются в SQL параметрами.
- Границы цены включительные, деньги — целые сомы. Фильтр времени ищет пересечение доступного окна выдачи с указанным интервалом сегодня или завтра по `Asia/Bishkek` (UTC+6). Можно задать только одну границу. Интервал через полночь вводится двумя отдельными поисками; `с > до` отклоняется.
- В каталоге видны `ACTIVE` с незавершённой выдачей сегодня/завтра, включая наборы без свободных порций. `WITHDRAWN`, `HIDDEN`, просроченные наборы и предложения заблокированных владельцев не показываются. На прямой странице снятого/просроченного набора показана причина недоступности; скрытый, отсутствующий набор и набор заблокированного владельца возвращают 404. Действий бронирования пока нет.

### Миграции и подключение

Используется существующая PostgreSQL из раздела запуска ниже; отдельная БД для каталога не нужна. Новая миграция `src/main/resources/db/migration/V5__offers.sql` автоматически применяется Flyway при следующем запуске приложения. `V4` уже занят восстановлением пароля. Старые миграции не менять, новую таблицу вручную перед запуском не создавать. Для своей базы укажите `DB_URL`, `DB_USER`, `DB_PASSWORD`. Для подключения из IntelliJ Database / DBeaver: PostgreSQL, host `localhost`, port `5433` при использовании `compose.yaml`, database `taketoday`, пользователь и пароль из `.env`.

Связи: `accounts.id ← establishments.owner_id`, `establishments.id ← offers.establishment_id`. В каталоге используются существующие название и адрес заведения, без дублирования в `offers`. Удаление заведения с предложениями ограничено внешним ключом.

| Поля `offers` | Тип и назначение |
| --- | --- |
| `id`, `establishment_id` | UUID: PK набора и FK заведения |
| `title`, `composition` | Название 3–150 символов и состав (`TEXT`) |
| `food_type` | `BAKERY`, `HOT`, `SALAD`, `DESSERT`, `SUSHI`, `DRINKS` |
| `photo_path` | Путь к фото, до 255 символов; демо-фото в `/images/offers/*.jpg`; будущие загрузки — `/uploads/offers/...` |
| `regular_price`, `discount_price` | INTEGER, обычная цена 1–100000, скидочная строго больше 0 и меньше обычной |
| `total_portions` | INTEGER 1–100 |
| `reserved_portions`, `sold_portions` | INTEGER ≥ 0, по умолчанию 0; сумма не больше общего количества |
| `pickup_start`, `pickup_end` | TIMESTAMP WITH TIME ZONE; конец строго позже начала; Java — `Instant`, отображение по Бишкеку |
| `status` | `ACTIVE` (по умолчанию), `WITHDRAWN` (снят продавцом), `HIDDEN` (скрыт администратором) |
| `created_at`, `updated_at` | Время создания/изменения, по умолчанию CURRENT_TIMESTAMP |
| `version` | BIGINT, по умолчанию 0; для будущей защиты конкурентных изменений |

Свободные порции = `total_portions - reserved_portions - sold_portions`. CHECK-ограничения защищают цены, счётчики и окно выдачи. Индексы: `(status, pickup_end)`, `(establishment_id)`, `(food_type, discount_price)`. Поиск по подстроке выполняется через `LOWER(title) LIKE`; отдельного полнотекстового индекса пока нет.

Для будущего кабинета продавца: использовать эту таблицу и enum `offer/FoodType`, не создавать вторую модель хранения. `OfferRepository` читает данные через `JdbcTemplate`, `CatalogService` задаёт публичный доступ, `CatalogController` обслуживает страницы Thymeleaf. `Offer` — публичная проекция с данными заведения, не JPA entity. При обновлениях нужно явно менять `updated_at` и `version`; автоматического `@Version`/триггера сейчас нет. Проверку владельца, загрузку фото и изменение счётчиков следует реализовать в сервисе продавца/брони.

Проверить данные можно SQL-запросом:

```sql
SELECT o.id, e.name AS establishment, o.title, o.food_type,
       o.regular_price, o.discount_price,
       o.total_portions - o.reserved_portions - o.sold_portions AS available,
       o.pickup_start, o.pickup_end, o.status
FROM offers o
JOIN establishments e ON e.id = o.establishment_id
ORDER BY o.pickup_start, o.id;

SELECT version, description, success
FROM flyway_schema_history ORDER BY installed_rank;
```

### Тестовые данные

При профиле `dev` (включён по умолчанию) `DevOfferData` транзакционно добавляет три демо-заведения и десять наборов: шесть видов еды, распроданный, снятый, просроченный и скрытый. Даты рассчитываются на день первого запуска и завтра по Бишкеку; наборы хранятся в БД, не являются заглушками интерфейса. Фотографии Unsplash включены в репозиторий и не требуют сети при просмотре (см. `static/images/offers/SOURCES.md`). Демо-учётки `catalog-demo-N@example.invalid` не подтверждены, имеют отключённый пароль и не предназначены для входа.

Повторный запуск не дублирует и не перезаписывает существующие строки, включая изменённые вручную. Даты сами не продлеваются: когда выдача завершится, наборы исчезнут из каталога. Для обновления демо-наборов в локальной БД выполните следующий запрос и перезапустите приложение с `dev`:

```sql
-- Только демонстрационные наборы с зарезервированными UUID; пользовательские данные не затрагиваются.
DELETE FROM offers WHERE id IN (
 'de000000-0000-4000-8000-000000000100', 'de000000-0000-4000-8000-000000000101',
 'de000000-0000-4000-8000-000000000102', 'de000000-0000-4000-8000-000000000103',
 'de000000-0000-4000-8000-000000000104', 'de000000-0000-4000-8000-000000000105',
 'de000000-0000-4000-8000-000000000106', 'de000000-0000-4000-8000-000000000107',
 'de000000-0000-4000-8000-000000000108', 'de000000-0000-4000-8000-000000000109'
);
```

UUID демо-владельцев заканчиваются на `000000000001`–`000000000003`, заведений — `000000000011`–`000000000013`, общий префикс `de000000-0000-4000-8000-`. Не использовать эти идентификаторы для пользовательских данных. Когда появятся заказы с FK на `offers`, удаление связанных наборов будет недоступно — для обновления демонстрации понадобится отдельная тестовая БД.

Отключить заполнение: переменная окружения `$env:APP_CATALOG_SEED_DEMO = "false"` или свойство `app.catalog.seed-demo=false`. В профиле `prod` данные не создаются. Отключение заполнения не удаляет ранее созданные записи. Тесты отключают автоматическое заполнение и создают собственные данные в H2.

Проверки каталога: `.\mvnw.cmd -Dtest=CatalogTests test`; все проверки и сборка: `.\mvnw.cmd verify`.

## Требования

- JDK 17 или новее; переменная `JAVA_HOME` должна указывать на JDK.
- Docker с Compose для локальных PostgreSQL и Mailpit либо собственная PostgreSQL.
- Доступ к интернету при первой сборке: Maven Wrapper скачивает Maven и зависимости. Отдельно устанавливать Maven не требуется.
- Node.js нужен только для необязательного отдельного frontend-сервера.

Все команды ниже выполняются из корня репозитория в PowerShell.

## Быстрый локальный запуск

### 1. Настройте базу

Создайте `.env` в корне проекта (файл исключён из Git). Можно начать с `.env.example`, но текущий пример содержит только `DB_USER`. Заполните:

```dotenv
DB_URL=jdbc:postgresql://localhost:5433/taketoday
DB_USER=taketoday
DB_PASSWORD=replace_with_local_password
PORT=8080
```

Замените пароль своим значением. Значения записывайте без кавычек, каждое на отдельной строке.

```powershell
docker compose -f compose.yaml up -d
docker compose -f compose.yaml ps
```

Используйте именно `-f compose.yaml`: этот файл запускает PostgreSQL 17 на порту **5433** и Mailpit. В репозитории также есть `docker-compose.yml` с PostgreSQL 16 на **5432**; это другой вариант конфигурации. Не смешивайте его порты с примером выше. База `taketoday` создаётся контейнером автоматически.

### 2. Запустите приложение

```powershell
.\start-backend.ps1
```

Скрипт читает настройки из `.env` и запускает Maven Wrapper. Если `MAIL_USERNAME` в `.env` не указан, письма уходят в локальный Mailpit из `compose.yaml` — отдельно задавать почтовые переменные не нужно.

Если порт 8080 занят (например, другим контейнером Docker), добавьте в `.env` строку `PORT=8081`.

Запуск без скрипта (например, если PowerShell запрещает `.ps1`):

```powershell
Get-Content .env | ForEach-Object { if ($_ -match '^([A-Z_]+)=(.*)$') { Set-Item "env:$($Matches[1])" $Matches[2] } }
$env:MAIL_USERNAME = "noreply@taketoday.local"; $env:MAIL_PASSWORD = "local-unused"
$env:SPRING_MAIL_HOST = "localhost"; $env:SPRING_MAIL_PORT = "1025"
$env:SPRING_MAIL_PROPERTIES_MAIL_SMTP_AUTH = "false"; $env:SPRING_MAIL_PROPERTIES_MAIL_SMTP_STARTTLS_ENABLE = "false"
.\mvnw.cmd spring-boot:run
```

После сообщения об успешном старте:

- Сайт: http://localhost:8080 — доступен без входа.
- Письма с кодами: http://localhost:8025 — интерфейс Mailpit.
- PostgreSQL: `localhost:5433`, база `taketoday`, учётные данные из `.env`.

Mailpit принимает письма для любых адресов локально. При регистрации можно использовать, например, `customer@example.com`, а код взять в Mailpit. Внешняя доставка писем при этой настройке не выполняется.

Миграции из `src/main/resources/db/migration` применяются автоматически при запуске. Hibernate проверяет схему (`ddl-auto: validate`).

### 3. Проверьте сценарий входа

Откройте сайт без регистрации, затем создайте аккаунт покупателя или представителя заведения. Для сотрудника заполните данные заведения. Введите шестизначный код из Mailpit. При повторном входе потребуются пароль и новый код из письма.

Код действует 10 минут, повторная отправка доступна через 60 секунд. После пяти неверных кодов нужно начать вход заново.

## Запуск в IntelliJ IDEA

1. Откройте `pom.xml` как Maven-проект и выберите JDK 17+.
2. Выполните Reload All Maven Projects.
3. Создайте Spring Boot/Application-конфигурацию с главным классом **`com.example.taketoday.TakeTodayApplication`**.
4. В Environment variables укажите значения `DB_URL`, `DB_USER`, `DB_PASSWORD` из примера и все почтовые переменные из раздела быстрого запуска. При необходимости добавьте `ADMIN_EMAIL` и `ADMIN_PASSWORD`.
5. Запустите приложение и откройте http://localhost:8080.

IDEA не получает переменные из другого окна PowerShell и не читает `.env` автоматически. В Maven-плагине основной класс уже указан явно.

## Доступ и роли

| Раздел | Доступ |
| --- | --- |
| `/`, `/index.html`, `/styles.css`, `/app.js`, `/css/**`, `/js/**`, `/uploads/**` | Всем, включая гостей |
| `/api/public/**` | Всем |
| `/api/auth/**` | Доступны до входа; отдельные операции проверяют данные и код |
| `/api/customer/**`, `/api/orders/**` | Только `CUSTOMER` |
| `/profile` | Любой вошедший пользователь |
| `/staff`, `/staff/**`, `/api/staff/**` | Только `STAFF` — сотрудник/продавец |
| `/admin`, `/admin/**`, `/api/admin/**` | Только `ADMIN` |
| Прочие маршруты | Требуют авторизации |

Проверка прав выполняется сервером. Гость получает `401` для защищённого раздела, вошедший пользователь с другой ролью — `403`. Для POST-запросов дополнительно требуется CSRF-токен. Публичный доступ к маршруту не означает, что любой запрос к нему будет принят без валидации.

Сейчас сведения о роли и доступном разделе отображаются на главной после входа. Реализованы API `/api/customer/home`, `/api/staff/home`, `/api/admin/home`. Бронирование и оплата пока не реализованы.

Страницы этапа 1 (Thymeleaf, по макету Figma), ссылки на них появляются в меню главной после входа:

| Адрес | Что на странице |
| --- | --- |
| `/profile` | Личный кабинет: имя, телефон, смена пароля. После смены пароля текущая сессия остаётся, остальные завершаются |
| `/staff` | Кабинет заведения: карточка заведения и часы работы на сегодня |
| `/staff/venue` | Сведения о заведении: название, категория, описание, адрес, район, контакты, логотип (JPG/PNG до 2 МБ), график по дням |
| `/admin` | Обзор админ-панели (число пользователей и заведений). Остальные разделы — этап 5 |

Сотрудник видит и меняет только своё заведение: оно ищется по `owner_id` вошедшего пользователя. Логотипы сохраняются в папку `UPLOAD_DIR` (по умолчанию `uploads` в корне проекта, папка исключена из Git).

Сессии хранятся через cookie `JSESSIONID`. Блокировка аккаунта и смена версии авторизации отзывают доступ; сброс пароля отзывает прежние сессии.

### Создание администратора

До запуска добавьте в `.env` (при запуске из IDEA — в Environment variables):

```dotenv
ADMIN_EMAIL=admin@example.com
ADMIN_PASSWORD=replace_with_strong_password
```

Пароль: от 10 символов, не более 72 байт UTF-8. При старте приложение создаст администратора, если такого аккаунта ещё нет. Используйте адрес, который не занят покупателем или сотрудником. Смена `ADMIN_PASSWORD` не обновляет пароль уже существующего администратора. Публичная регистрация с ролью `ADMIN` запрещена. Администратор также входит с кодом из письма.

## Другие варианты запуска

### Собственная PostgreSQL

Создайте пользователя и базу `taketoday`, затем укажите их в `DB_URL`, `DB_USER`, `DB_PASSWORD`. Пользователь должен иметь права на создание таблиц и применение миграций. Пример URL: `jdbc:postgresql://localhost:5432/taketoday`. Docker для базы в этом варианте не нужен. Почту настройте отдельно.

### Реальная почта

Вместо блока Mailpit задайте `MAIL_USERNAME` и `MAIL_PASSWORD` для Gmail (пароль приложения), убрав переопределения `SPRING_MAIL_*`. Текущий `application.yml` использует `smtp.gmail.com:587`, SMTP AUTH и STARTTLS; отправителем служит `MAIL_USERNAME`. Для другого провайдера переопределите соответствующие `SPRING_MAIL_*`. Переменные `SMTP_*` и `MAIL_FROM` в текущей конфигурации не подключены к этим свойствам.

### Отдельный frontend-сервер

Для обычного запуска Node.js не требуется: Spring Boot раздаёт сайт на 8080. Если нужен отдельный сервер, запустите backend, затем в другом окне:

```powershell
.\start-frontend.ps1
```

Откройте http://localhost:5173. Сервер `frontend/server.mjs` читает те же файлы из `src/main/resources/static` и проксирует `/api/` на `http://localhost:8080`. Для другого backend задайте `API_URL`, для другого frontend-порта — `FRONTEND_PORT`. Используйте один и тот же адрес сайта в рамках сессии.

- `src/main/java/com/example/taketoday/auth` — авторизация и регистрация.

Использует общие стили `css/app.css` и шрифты `fonts/`, как страницы кабинетов. Ранее файлы находились в `frontend`; перенос устраняет 404 из-за отсутствия ресурсов в сборке.
- `src/main/resources/db/migration` — миграции Flyway.

- `src/test/java/com/example/taketoday/HomePageTests.java` — проверки публичной главной и защищённых разделов.

## Диагностика

| Симптом | Что проверить |
| --- | --- |
| Whitelabel `401` на главной | Правильный класс запуска, актуальность кода и полный перезапуск приложения |
| Whitelabel `404` на главной | После Maven-сборки должен существовать `target/classes/static/index.html`; обновите Maven-проект, пересоберите и перезапустите |
| Ошибка подключения к БД | Для `compose.yaml` используйте порт 5433; проверьте `docker compose -f compose.yaml ps` и данные `.env` |
| Ошибка пароля PostgreSQL после изменения `.env` | Пароль контейнера задаётся при первой инициализации volume; изменение `.env` не меняет пароль существующей БД |
| Ошибка `${MAIL_USERNAME}` / `${MAIL_PASSWORD}` | Задайте обе переменные в окружении запуска; одного `.env` для них недостаточно |
| `503` при отправке кода | Доступность SMTP, Mailpit и почтовые настройки текущего процесса |
| `403` при POST | Получите новый токен через `/api/auth/csrf` и передайте его вместе с cookie сессии |
| `401` после подтверждения кода | Cookie `JSESSIONID`, единый адрес `localhost`, актуальность сессии |
| `429` | Пауза между письмами 60 секунд и лимит попыток в 15-минутном окне |
| PowerShell запрещает `.ps1` | Используйте разрешённую в вашей среде политику либо задайте переменные вручную и выполните `.\mvnw.cmd spring-boot:run` |

Остановка приложения: `Ctrl+C`. Остановка контейнеров с сохранением данных:

```powershell
docker compose -f compose.yaml down
```
